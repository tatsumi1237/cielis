# 疑問→飛躍型ナレーション（gimon-narration）

テーマ（例：「もしも、人類が100人になったら？」「冷蔵庫を開けっぱなしにしたら部屋は涼しくなる？」）を受け取り、**台本 → ユーザーの目視チェック → 音声生成** の順に進める。映像は音声の長さに合わせて後から作る（ナレーション先行）。

関連ファイル（このフォルダ内）：
- `references/edit-history.md` … ユーザーが台本を直した履歴と、そこから取り出したルール（**台本を書く前に必ず読む**）
- `references/readings.md` … 読み間違い対策の辞書と、モデル・声・設定の決定記録（**音声を作る前に必ず読む**）
- `references/example-100nin.md` … ユーザーが完成させた台本の見本（字幕用・音声用）
- `scripts/tts.py` … 音声生成スクリプト（既定が決定済みの設定）

## 絶対ルール
1. **台本のOKが出る前に音声を生成しない。** 生成は無料枠・クレジットを消費する。「OK」の返事を待つ。
2. **台本はテキストでチャットに貼る。** コードブロックでコピーしやすく。表や図にしない。
3. **台本は完全オリジナル。** 参考動画やほかの作品の文言・オチをなぞらない。構成の型だけを使う。
4. **API キーをチャットに貼らせない・表示しない。** 環境変数 `ELEVENLABS_API_KEY` から読む。確認は「有無・長さ・`sk_` で始まるか」だけ。
5. **聞いていない音声の出来は断言しない。** 日本語の発音・抑揚・間は、ユーザーに聞いて判断してもらう。

## 手順

### 1. テーマの確認と事実の下調べ
- テーマが「疑問」の形でなければ、素朴な疑問の形に直す。
- 仕組み・数字は、確かなものだけを台本に使う。怪しい断定は避け、必要なら下調べ（WebSearch）をする。
- 出典や前提が要る数字は、台本のあとに別メモで添える。確率などの**計算した数字は台本に入れない**（修正履歴の⑦）。

### 2. 台本を作る（`references/edit-history.md` のルールを最初から反映する）
**目標：約80〜90秒・約400〜470文字**（1分未満は「短い」と言われた）。eleven_v3 の Will は約5文字/秒。短い文を重ねる。1段落＝1カット候補。

型は2つ。テーマに合うほうを選ぶ。

**型A「もしも〜になったら」（メリット→転換→デメリット→まとめ）** ※100人の見本
| 段 | 役割 |
|---|---|
| ① 問いかけ | 「もしも、○○が△△になったら？」 |
| ② メリット | **3つ**。得をした感じが出る具体的な絵（独占・貸し切り・選び放題）。抽象論は入れない |
| ③ 転換 | 「……でも実は、困るのは、「○○」なんです。」（1文で。前置きしない） |
| ④ デメリット | 「たとえば〜」「じゃあ、〜したら？」と話を移す。**命・生活への緊急性が高い順**。各項目＝短い事実＋その結果 |
| ⑤ まとめ | 「つまり、〜」で結論。**デメリットの語を回収**する（例：電気の無い中） |
| ⑥ オチ | 「……つまり、○○が△△になったら、最終的に、〜になります。」と、**冒頭の問いかけと同じ形**で言い切る |

**型B「疑問→逆転」（仕組み解説型）** ※冷蔵庫の見本：問いかけ→思い込み→「……と思いますよね。でも実は、逆なんです」→仕組み→結論→次の疑問→答え→飛躍→オチ。疑問と答えを最低2回転させ、オチは直前の話に論理でつなげる。

守ること：
- 疑問に**ちゃんと答える**（ウソや雑な断定で飛躍しない）。
- ですます調で統一（常体の言い切りを混ぜない）。
- 間を作りたい箇所は「……」「、」、強調したい語は**独立した行**にする（例：「たとえば電気。」で改行）。
- 読み上げて意味が通る言葉にする。
- **句読点は音声と字幕で扱いが違う**：台本・音声用の文は、句読点を**残す**（間・抑揚になる）。字幕は台本の句読点や意味の切れ目で**改行し、行末の「、」「。」は付けない**（行の途中の読点と「？」は残す）。字幕の作り方は `gimon-video-build/references/text-spec.md`。

### 3. ユーザーに台本を見せてチェックしてもらう
1. 台本全文を `text` のコードブロックで貼る（段落ごとに空行）。
2. 文字数と読み上げの目安秒数（約5文字/秒）。
3. 事実関係の注意点があれば1〜2行（数字は「約」「およそ」、計算の根拠も書く）。
4. 質問は1つだけ：「このままでOKですか？ 直したい箇所があれば教えてください」。

直しが入ったら、直した台本を**もう一度全文貼る**。ユーザーが自分で直した全文を貼ってきたら、それを最終稿として保存し、**差分を `references/edit-history.md` に追記**する。

### 4. 音声を生成する（OKが出てから）
**決定済みの設定**（ユーザーが聞き比べて選んだもの。変えない）：

| 項目 | 値 |
|---|---|
| モデル | `eleven_v3` |
| 声 | Will（男性・明るい）`bIHbv24MWmeRgasZH58o` |
| 設定 | stability 0.5 ／ style 0.0 ／ similarity 0.75 |

`eleven_multilingual_v2` は日本語が不自然だったので**使わない**。全文ひらがなも不自然になるので**やらない**。

準備（キーが未設定のときだけ）：
1. ユーザーに ElevenLabs へサインインしてもらう（ログインやアカウント作成は代行しない）。
2. ブラウザで `https://elevenlabs.io/app/developers/api-keys` を開き、**キーの作成はユーザー本人に**してもらう（作成時にしか値が表示されないため、会話に出さない）。権限は Text to Speech だけで足りる。
3. ユーザーが自分で設定する：Windows は `setx ELEVENLABS_API_KEY "ここにキー"`（新しいターミナルから有効）、Mac／Linux は `export ELEVENLABS_API_KEY=...`、**クラウド環境は環境設定のシークレット（環境変数）に `ELEVENLABS_API_KEY` として登録**する。
4. 確認は**長さ51・`sk_` で始まる**ことだけ。24文字や `set` で始まる→置き換え忘れ。形式が正しいのに 401→Text to Speech 専用キーは購読情報・モデル・声の一覧が 401 になる（正常）。数文字のテスト生成で判断する。

手順：
1. **音声用の台本**（`script_xxx_tts.txt`）を作る。`references/readings.md` の辞書だけを適用する。**字幕は元の漢字の台本を使う。**
2. 生成：
   ```
   python -I <このスキルのフォルダ>/scripts/tts.py --text-file script_xxx_tts.txt --out narration.mp3
   ```
   （声・モデル・設定は既定が決定済み。声を試すときだけ `--voice` を渡す。）
3. 無料枠は月の文字数に上限がある。**撮り直しは枠を食う**。声や読みの確認は短い区間（最初の数行）で行い、決まってから全文を作る。無料枠で使える声は標準の声（premade）だけで、ライブラリの声（Rachel など）は 402。
4. 代替（無料枠が尽きた・キーが使えない）：Higgsfield の `generate_audio`（`text2speech_v2`・`variant: elevenlabs`）。**クレジットを消費する**ので `get_cost` で見積もり、ユーザーの了解を得てから使う。

### 5. 納品
1. `ffprobe` で総尺を測り、`ffmpeg -af silencedetect=noise=-35dB:d=0.45` で無音位置を出す。
2. mp3 を `SendUserFile` でチャットに送る（`display` は `attach`）。
3. 総尺・声・使った文字数をひと言で報告する。生成のたびに長さは数％ぶれる（同じ台本で81秒と86秒）ので、**最終の音声で測り直す**。
4. 質問は1つ：「読み間違いはありませんか？」。見つかった語は `references/readings.md` に追記する。

### 6. 映像へ引き継ぐ（ナレーション先行）
OKが出たら、無音位置と各行の長さから**カットの切れ目と尺**を決め、字幕も声のタイミングに揃える。音声を映像に合わせて伸縮しない。冒頭の問いかけは最初の3〜3.5秒に収める。
映像づくりは **`gimon-video-build` スキル**に引き継ぐ（くっきり・文字の大きさ・間延び防止・指摘履歴のルールはそちらに集約）。

## よくある失敗
- 台本の確認前に生成して、無料枠を無駄にする。
- キーをチャットに貼ってもらう・表示する。
- 全文をひらがなにして、イントネーションを壊す。
- メリットを抽象論（「自然が戻る」など）で並べる／デメリットに緊急性の低い話を入れる。
- オチが前の話とつながらず、唐突になる／冒頭の問いかけと形が揃わない。
- 計算した確率など、検算が要る数字を台本に入れる。
- 聞き比べを全文で何度もやり、枠を使い切る。
