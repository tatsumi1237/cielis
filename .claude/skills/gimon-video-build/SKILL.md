# 疑問→飛躍型ショート動画の制作（gimon-video-build）

`gimon-narration` で作った台本と音声（ElevenLabs）を受け取り、**ナレーションの長さに合わせて**映像を作る。見本は「もしも、人類が100人になったら？」（87.2秒・ユーザー承認済み）。

**作業の前に必ず読む：**
- `references/feedback-log.md` … ユーザーから受けた指摘21件と、そこから決めたルール（**同じ指摘を二度受けない**）
- `references/techniques.md` … 間延びさせない工夫・カメラ・数の見せ方・音・オチ
- `references/text-spec.md` … テロップ・数字の仕様書（用途ごとの大きさ・位置・色・句読点・行の長さ・強調）
- `references/tech-pitfalls.md` … ぼやけ・描画の不具合・書き出しの落とし穴と対処

**使い回す部品（`assets/`）：**
- `render.js` … 簡易サーバーを立て、Playwright で連番JPEG（品質97）を書き出す（Windows はGPU、Linux／クラウドはソフトウェア描画で自動切替）。プロジェクトのルートで実行し、`PAGE=/<フォルダ>/index.html` で対象を指定。`SUB=6` が本番、`SUB=1` が試し撮り
- `index.html` … 字幕・数字表示の DOM と CSS（文字サイズの確定値入り）
- `example-scene.js` … 見本の全シーン（後処理・空・人型・群衆・車・海・草・夜の街・火など）。新しい動画はここから必要な部品をコピーして使う
- `example-audio.py` … 効果音とBGMの合成（numpy/scipy）。場面ごとに節を足す
- `mux.sh`（Linux／Mac／Git Bash）／`mux.ps1`（Windows PowerShell）… 連番＋ナレーション＋効果音/BGM → mp4（ナレーションは loudnorm、BGMは声でダッキング）。`.ps1` は**ASCIIのみで編集すること**
- `sheet.sh`／`sheet.ps1` … 試し撮りのコマを横に並べた比較画像を作る

プロジェクトの配置（**どのPC・クラウドでも同じ**）：プロジェクトのルート `<project>/` に `node_modules`（three 0.160・playwright）を1回だけ入れ、動画ごとに `<project>/<動画名>/`（index.html・scene.js・audio.py）を作る。`render.js`・`mux.sh`・`sheet.sh` は `<project>/` にコピーして、ルートで実行する。

**環境の準備（クラウド／Linux の最初に1回）：**
```bash
cd <project> && npm init -y >/dev/null && npm i three@0.160.0 playwright && npx playwright install --with-deps chromium
sudo apt-get install -y ffmpeg fonts-noto-cjk   # 権限が無ければ apt-get install -y ...（日本語フォントが無いと字幕が四角になる）
pip install numpy scipy pillow faster-whisper    # 効果音・BGM合成／位置合わせ／ナレーションの文字起こし
```
- クラウドにはGPUが無いので、書き出し（`render.js`）は**Windowsの数倍〜十数倍遅い**。区切りごとに範囲を絞って書き出し、長いものは裏で実行する。
- ナレーション音声（ElevenLabs）のキーは、環境変数 `ELEVENLABS_API_KEY` に設定する（クラウドは環境設定のシークレットに登録）。
- 以降のコマンド例の `powershell -File xxx.ps1` は、Linux／クラウドでは `bash xxx.sh`（引数は同じ順）に読み替える。

## 絶対ルール（違反すると必ず指摘される）
1. **くっきり**：被写界深度（BokehPass）と動きのブレは**一切使わない**。ジッターAA＋軽いシャープ。共有版も強く圧縮しない。
2. **文字**：Noto Sans JP、白＋黒の縁取り、強調は金色。**タイトル114px／字幕88px／大きな数字180px**。冒頭タイトルと主役の数字は**画面中央**。**字幕の行末の句読点（、。）は付けない**（カット表を書く段階から）。1行は88pxで9字まで、4行まで。**全数値は `references/text-spec.md`**。
3. **人物**：歩く・座る・寝転ぶ・立つだけ。細かい動作は作らない。「独占・貸し切り」には**一人で過ごす人**を入れる。
4. **内容と矛盾しない**：小物・光・音を足すたびに台本と照合（例：電気が無い世界に電球を置かない）。
5. **間延びさせない**：1台詞＝1カット、1〜4秒。カメラは常に動かす。数・状態は「動く映像」で見せる。引きの空白は背景で埋める。
6. **確認は静止画**で。納品のたびにスマホへ通知（PushNotification）。
7. **安全枠**：文字・数字は **x=110〜970（左右110pxの内側）**。Instagram の再生画面は動画の左右を47〜約96px切る（投稿後に「横が切れた」と指摘された）。書き出し前に `assets/measure-edges.js` で全カットの端を測り、枠を外れる行が0件であることを確認する。

## 手順

### 1. ナレーションを区切る
- `ffmpeg -i narration.mp3 -af silencedetect=noise=-38dB:d=0.18 -f null -` で無音位置を出し、台本の各行に開始・終了秒を割り当てる。
- 映像の総尺はナレーション＋約1.5秒（最後の暗転）。

### 2. カット表を作る（作り始める前にユーザーへ表で見せる）
列：**時間｜台詞｜映像（場面・被写体・カメラの動き）｜使う手法（techniques.md の番号）｜効果音**。
- 4秒を超える台詞は2〜3カットに割る。終盤ほど細かく。
- 各カットで「何が動くか」（数・明かり・カメラ・人）を必ず1つ以上書く。
- 小物の矛盾チェック（ルール4）をこの段階で行う。

### 3. 作る（区切りごとに）
- 冒頭10〜15秒 → 中盤 → 終盤、のように**区切って**作り、各区切りで静止画確認 → 書き出し → 納品 → OK を待つ。
- 試し撮り：`SUB=1` で各カット2〜4コマ → `sheet.sh`（Windows は `sheet.ps1`）で横並び → 自分で確認（文字のはみ出し・人物の見切れ・最初のフレームの異物・逆光・空の黒）。**文字の左右の端は `assets/measure-edges.js`（全カットを0.4秒刻みで測る）で数値確認**し、x=110〜970 の外が0件であること。
- 本番：`SUB=6`。変えたカットのフレーム範囲だけ上書きで書き出す（テロップを変えた時は全編）。

### 4. 音
- `example-audio.py` の形で、場面ごとに環境音・同期効果音・曲を足す（techniques.md の6）。
- 曲の緩急：明るい → 「でも実は」で暗く → 重い締めで無音＋「ピー」 → 明るく戻る → 最後は温かい和音。

### 5. 合成と納品
- Linux／クラウド：`bash mux.sh <frames_dir> <narration.mp3> <fx.wav> <out.mp4> <秒>`
- Windows：`powershell -File mux.ps1 -frames <dir> -narr <narration.mp3> -fx <fx.wav> -out <out.mp4> -dur <秒>`
- 共有版：2パス・7〜9Mbps。30MBを超えるなら、新しく作った区間だけ切り出すか、前後半に分割。
- `SendUserFile`（display: render）→ `PushNotification`（何ができたか・何を確認してほしいかを1行）。
- 報告には、変えたこと・確認できていないこと（**音は聞けない**こと、人型はデフォルメであること）を必ず書く。

### 6. 投稿セクションへ渡す（「投稿して」と言われてから）
**この手順は、ローカルのWindows PCにある `poster/`（自動投稿の仕組み）がある場合だけ。クラウド環境にはないので、クラウドでは動画（`<テーマ>_スマホ用.mp4`）と投稿文（`投稿文.md`）をユーザーに渡すところまでで終える。**
制作セクションは **`.env` やアップロードのコードに触らない**（inbox のファイルを動かす・投稿先を絞るなどもしない）。
1. 投稿文は `moshimo-post-writer` で作り、**ユーザーのOKを得る**。投稿用の動画は `<テーマ>_スマホ用.mp4`（64MB未満、2パス約5Mbps）。
2. `poster/` で `python post_agent.py submit-md "<テーマ>_スマホ用.mp4" "投稿文.md"` を1行実行し、続けて shorts-poster に投稿を依頼する（`python post_agent.py run` でも可）。
3. 報告は SNS ごとに **SNS名 / 結果（成功・失敗・下書き・予約）/ 原因 / ユーザーのやること（なければ再実行）**。エラーを隠さない。文面を勝手に変えない。成功したSNSは再投稿しない。
4. 既知：YouTube は1日の上限で失敗しうる（翌日再実行）・毎日20時に予約公開・監査前は強制非公開。TikTok は下書きに届く（アプリで「投稿」）。Instagram は一時置き場（uguu.se）経由、使えなければ失敗として報告。

### 7. 指摘を受けたら
- 直して再納品したあと、新しい指摘は `references/feedback-log.md` に追記し、必要なら絶対ルールにも足す。
